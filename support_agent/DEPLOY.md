# Как запущены бот магазина и помощник

Эта инструкция для Александра. В ней два разных сервиса на Railway. Они не заменяют друг друга.

Магазинный бот продаёт подписки, принимает оплату, обрабатывает ссылки на оплату и активирует ChatGPT, Claude и остальные сервисы. Консультаций внутри этого бота больше нет.

Помощник отвечает клиентам в личной переписке Александра через Telegram Business. Запускается командой `python -m support_agent.service`.

## Что в репозитории говорит о деплое

В репозитории нет `railway.toml` и `railway.json`. Поэтому ветка автодеплоя здесь не зафиксирована. Обычно Railway сам выкатывает ту ветку, которая подключена к сервису в панели. Чаще всего это `main`, и выкат идёт при каждом push в неё. Это нужно проверить глазами: сервис → Settings → Source. Если там не `main`, push в `main` этот сервис не обновит.

Магазинный бот, если собран через Procfile/Nixpacks: в корне лежит `Procfile` со строкой `worker: python bot.py`. Отдельного Dockerfile у магазина в репозитории нет. Корень сервиса — корень репозитория. Стартовая команда — `python bot.py`.

Помощник: `support_agent/Dockerfile`. Внутри команда `python -m support_agent.service`. В переменных этого сервиса должно быть `RAILWAY_DOCKERFILE_PATH=support_agent/Dockerfile`. Корень тоже корень репозитория, не папка `support_agent`, иначе файл Dockerfile не найдётся по этому пути. Публичный домен помощнику не нужен: он сам опрашивает Telegram.

Оба сервиса не должны использовать один и тот же токен бота.

## Порядок выкладки четырёх правок

Сейчас четыре последовательных запроса: #3, затем #4, затем #5, затем этот. Каждый следующий смотрит на ветку предыдущего, а не сразу на `main`.

Вливать по порядку #3 → #4 → #5 → #6. После каждого вливания в `main` у следующего запроса нажать смену базы на `main`, если GitHub сам этого не сделал. Тогда в проверке виден только новый кусок. Не вливать верхний запрос в `main`, пока нижние не влиты: иначе магазин получит сразу все изменения без промежуточной проверки.

## Магазинный бот

Нужные переменные остаются теми, что уже стоят на боевом сервисе магазина: токен магазинного бота, база, FreeKassa и остальные ключи оплаты. Эта инструкция их не меняет и не просит копировать в git.

После выкладки клиент в боте может открыть каталог, оплатить и активировать подписку. Если он просто напишет вопрос, бот предложит каталог и кнопку «Написать Александру». Старый консультант на Claude внутри бота больше не отвечает. Продажа подписки Claude и фоновые проверки кодов остаются.

## Помощник

Отдельный сервис. Один том с точкой монтирования `/data`. Одна копия, без второго процесса с тем же токеном.

Переменные:

- `SUPPORT_BOT_TOKEN` — токен бота помощника, не токен магазина.
- `SUPPORT_OWNER_ID` — числовой Telegram ID Александра.
- `OPENAI_API_KEY` — ключ модели.
- `SUPPORT_MODEL` — модель ответов. Сейчас в примере `gpt-4.1-mini`.
- `SUPPORT_AUDIO_MODEL` — расшифровка голоса. Сейчас в примере `gpt-4o-transcribe`.
- `SUPPORT_STATE_PATH` — `/data/support.sqlite3`.
- `SUPPORT_MEDIA_CONSENT` — `yes`, только если согласны отправлять фото и голос тестовых чатов в модель.
- `SUPPORT_DAILY_CALL_LIMIT` — сколько запросов к модели в сутки по UTC. Не менять без отдельного решения. Это не лимит в рублях. Фото и расшифровка голоса входят в этот счётчик. На 80% и на 100% Александру приходит одно предупреждение за сутки. Когда лимит выбран, клиенту уходит фраза «Александр будет на связи…», а не молчание.
- `SUPPORT_CATALOG_TTL_SECONDS` — необязательно. Сколько секунд снимок каталога считается свежим, прежде чем перед ценой прочитать его снова. По умолчанию 900 (15 минут). Допустимо от 60 до 21600. Если повторное чтение не удалось, остаётся прошлый снимок, а ответ с ценой клиенту не отправляется.
- `SUPPORT_TEST_CHAT_IDS` — кого помощник вообще читает. Для проверки: `8939620159` (второй аккаунт @antonidrudiger). Несколько ID через запятую.
- `SUPPORT_AUTO_TEST_CHAT_IDS` — кому можно отвечать самому, без кнопки «одобрить». Для проверки тот же `8939620159`. Старое имя `SUPPORT_AUTO_TEST_CHAT_ID` тоже принимается, если нужен один ID.
- `SUPPORT_DRAFTS_FOR_ALL` — `yes`: помощник читает всех клиентов в личке и присылает Александру черновик в этот бот. Клиенту сам ничего не отправляет. Автоответы по-прежнему только для ID из `SUPPORT_AUTO_TEST_CHAT_IDS`. Чат, где помощник не нужен (друзья, партнёры), выключается кнопкой «Отвечаю сам».
- `SUPPORT_AUTO_FOR_ALL` — оставить пустым. Значение `yes` включает автоответы для всех ID из `SUPPORT_TEST_CHAT_IDS`. Пока пусто, остальные клиенты автоответ не получают.
- `RAILWAY_DOCKERFILE_PATH` — `support_agent/Dockerfile`.
- `SHOP_READONLY_DATABASE_URL` — необязательно. Отдельный логин только на чтение, не боевой `DATABASE_URL` магазина.
- `SUPPORT_SHOP_URL` и `SUPPORT_SHOP_READ_TOKEN` — необязательно, если подключён живой каталог магазина по адресу `/api/support/catalog`. Токен не короче 32 символов и должен совпадать с `SUPPORT_SHOP_READ_TOKEN` на магазине.

После старта Александру в бота помощника приходит сообщение, что сервис запущен и в каком он режиме.

## Разговорные названия

Файл `support_agent/data/aliases.yaml`. В нём у каждого сервиса каталога есть разговорные формы: транслит, опечатки, короткие имена. Отдельный список `tariff_words` — слова вроде «годовая» и «месячная». Отдельные фразы, например «чат гпт плюс», лежат в `phrases`.

Чтобы добавить слово, допишите его в `aliases` нужного сервиса. Поле `id` должно совпадать с ключом этого товара в каталоге. Одно и то же слово нельзя поставить двум сервисам. Файл читается как подсказка для модели. По совпадению слова бот сам сервис не выбирает. Если модель не уверена, она спрашивает два-три конкретных варианта из каталога.

Правка попадает к клиентам после нового выката помощника: файл лежит внутри образа. Новых переменных для этого файла нет.

Фото клиентского скрина входит в тот же запрос разбора, что и текст. Модель берётся из `SUPPORT_MODEL`; для картинок она должна уметь смотреть изображения, сейчас это `gpt-4.1-mini`. Такой ход считается одной тратой дневного лимита `SUPPORT_DAILY_CALL_LIMIT`, но сам запрос тяжелее обычного текста. Голос — отдельная расшифровка моделью `SUPPORT_AUDIO_MODEL` и затем обычный текстовый разбор. Это две траты лимита. Повторно уже расшифрованный голос не отправляется. Лимиты одного обращения: 3 фото, 2 голосовых, вместе не длиннее 180 секунд, один файл до 8 МБ, все вложения до 16 МБ. Чек по-прежнему уходит Александру и сам по себе оплату не подтверждает.

## База: цены и заказы для помощника

Если задан `SHOP_READONLY_DATABASE_URL`, на боевой базе магазина один раз выполнить файл `support_agent/sql/support_readonly.sql` из-под владельца таблиц. Он создаёт представление каталога и функцию процентов для цены клиента. Роли помощника выдать только чтение, как написано комментариями в конце этого файла. Права на запись этой роли давать нельзя: помощник откажется запускаться.

Пока SQL не применён, помощник не должен говорить клиенту, что заказ не оплачен. Он скажет, что проверка сейчас недоступна.

Живой каталог через `/api/support/catalog` заказы не отдаёт. Заказы читаются отдельно и только если они принадлежат этому клиенту.

Снимок цен у помощника живёт не дольше `SUPPORT_CATALOG_TTL_SECONDS`. Отдельно официальный поиск функций может помнить ответ до 6 часов, а аварийный кэш наличия в самом магазине — тоже до 6 часов. На цену, которую помощник называет клиенту, это не заменяет свежий снимок каталога: перед такой ценой снимок старше порога читается заново.

## Конфликт и ваши сообщения

Если модель видит злость, угрозу возврата, жалобы или тот же нерешённый вопрос второй раз, клиенту уходит только фраза про Александра. Вам приходит короткое сообщение с причиной и последними репликами. Повтор такого сигнала в том же чате не чаще одного раза в 30 минут.

Ваша ручная реплика в чате на 10 минут останавливает помощника, как и раньше. В окне последних 10 сообщений она помечена как ваша и для модели важнее его черновика: он не должен ей противоречить, повторять её или спрашивать то, что вы уже спросили. После паузы он продолжает от вашей последней реплики.

## Ответы, которых нет в каталоге

Список тем без вашего текста: `support_agent/data/owner_only_topics.md`. Тексты: `support_agent/data/faq.yaml`. Уже записано только это: гарантия на все сервисы, кроме Claude; Claude может заблокировать аккаунт, на него гарантии нет, на остальные блокировка входит в гарантию; активация занимает 5–30 минут, у сервисов с автоактивацией — 2–5 минут. Возврат не обещается: бот собирает номер заказа, сервис и причину и передаёт их вам. С 11.11.2026 добавлены темы: оплата картой и /start, зависший бот, продление без автосписаний, письмо об отмене автопродления, перенос подписки, PayPal и иностранные карты, покупка для другого человека, чек, сервис вне каталога. Пустой `answer` без списка `collect` по-прежнему означает фразу про Александра. После правки файла нужен новый выкат. Новых переменных для этого нет.

## Как быстро выключить автоответы

В личке с ботом помощника отправить `/stop`. Новые автоответы прекращаются. Уже ушедшее в Telegram сообщение это не отзывает.

Повторно не включать, пока не проверите `/status`.

`SUPPORT_AUTO_FOR_ALL` при этом сам не стирается. Если он равен `yes`, после нового включения режима автоответы снова смогут идти всем из тестового списка. Чтобы закрыть это насовсем, очистить `SUPPORT_AUTO_FOR_ALL` и перезапустить сервис помощника.

## Проверка на аккаунте 8939620159

Перед этим в переменных помощника стоят `SUPPORT_TEST_CHAT_IDS=8939620159` и `SUPPORT_AUTO_TEST_CHAT_IDS=8939620159`. `SUPPORT_AUTO_FOR_ALL` пустой. Другим клиентам помощник не отвечает.

1. С аккаунта @antonidrudiger открыть личку Александра и написать обычный вопрос, например про установку ChatGPT.
2. Первый ответ помощника начинается с фразы «Здравствуйте! Я ИИ-помощник Александра, помогу с вопросами по нейросетям и оформлению подписок)» и сразу отвечает на вопрос. Второй вопрос в том же чате уже без повторного представления.
3. Написать «курсор пропал» и «видео для ютуб». Помощник уточняет, о чём речь, и не просит почту или пароль.
4. Написать «забыл пароль» и «не приходит код». Приходит нормальный совет, а не заглушка «сообщение скрыто».
5. Александру ответить в этом чате самому. 10 минут помощник молчит. Сообщение, которое Александр закрыл, помощник потом не повторяет. Новое сообщение клиента после паузы получает ответ.
6. Написать «позови человека» в 15:00 по Москве и после 22:00. В обоих случаях есть фраза «Александр будет на связи в течение получаса-часа». Предупреждение о задержке есть только вне 10:00–22:00, в том числе в субботу и воскресенье днём его нет.
7. Спросить про монетки. Ответ только про 10% с первой покупки друга и оплату подписки. Других способов нет.
8. В магазинном боте с того же аккаунта нажать «Вопрос Александру» и написать произвольный текст. Старый консультант не отвечает. Есть каталог и ссылка написать Александру. Оплата и кнопка активации подписки Claude на месте.
9. Если что-то пошло не так, `/stop` у помощника. Потом разобрать чат и только после этого включать снова.

Локальная проверка кода, не для телефона: `python3 -B -m unittest discover -s tests -p 'test_support*.py'`.
