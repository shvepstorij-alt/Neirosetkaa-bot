# Тестовый помощник: запуск отдельного сервиса

Это исполняемая версия для проверки с владельцем, не готовые автоответы для всех
клиентов. Клиенту сообщение отправляется ТОЛЬКО после кнопки «Одобрить и отправить».
AUTO намеренно отсутствует до проверки качества и всех ограничений на реальной модели.

## Что работает в коде

- Long polling отдельного бота neirosetkaalexbot, бизнес-подключение только владельца.
- Белый список Telegram ID тестовых клиентов. Пустой список = никто не обрабатывается.
- OFF/DRAFT глобально и для чата. Ручной ответ владельца ставит чат в OFF.
- Сохранение состояния SQLite на отдельном Volume. Один процесс/одна реплика.
  Изменение относительно первоначального плана PostgreSQL: для пилота SQLite с
  блокировкой процесса; перед масштабированием потребуется переработать хранилище.
- Текст, Telegram voice OGG до 180 секунд/8 МБ, фото и изображения-документы
  JPEG/PNG/WEBP до 8 МБ и 20 млн пикселей. Другие вложения — ручная обработка.
- OpenAI Responses со структурированным ответом; без инструментов модели.
- Отдельная карточка черновика владельцу: разбор, текст ответа, кнопки управления.
- Перед отправкой — свежие права Telegram, ревизия чата, последнее сообщение,
  окно ответа и срок черновика 15 минут. Повторный клик не дублирует отправку.
- Неопределённый результат отправки помечается uncertain и не повторяется.
- Счётчик запросов OpenAI: по умолчанию 100/сутки UTC. Голосовое обычно требует
  два запроса. Это НЕ лимит долларов, стоимости токенов ещё нужно измерить.

## Перед настройкой

1. Владелец должен нажать Start у @neirosetkaalexbot, иначе сообщения управления
   не доставляются и сервис завершит запуск до обработки клиентов.
2. Подготовить API-ключ OpenAI и токен ИМЕННО нового бота, не токен магазина.
3. SUPPORT_OWNER_ID — числовой Telegram ID владельца (ваш личный ID из ADMIN_IDS
   действующего магазина). Не username, не весь список и не ID самого бота.
4. Не подключать реальные клиентские переписки на первом тесте. Нужен другой
   аккаунт/доброволец с тестовыми сообщениями без паролей и реквизитов.

## Railway

1. Загрузить папку support_agent в тот же репозиторий, сохранив структуру.
   Текущие bot.py, Procfile и requirements.txt магазина не менять.
2. Создать НОВЫЙ сервис из этого репозитория. Root Directory — корень репозитория.
3. У нового сервиса задать RAILWAY_DOCKERFILE_PATH=support_agent/Dockerfile.
   Start Command оставить пустым (используется CMD) либо python -m support_agent.service.
4. Создать Volume для НОВОГО сервиса с точкой монтирования /data. Это обязательно:
   без него теряется состояние остановки, история и защита отправок после рестарта.
5. Одна реплика, без public domain и HTTP healthcheck: это polling worker.
   Не запускать одновременно на ноутбуке и в Railway с одним токеном.
6. Внести переменные из env.example. Ключи только в Railway, не в git или чат.
   SUPPORT_TEST_CHAT_IDS сначала можно оставить пустым.
7. SUPPORT_MEDIA_CONSENT=yes означает согласие передавать изображения и голосовые
   выбранных тестовых чатов OpenAI. Изображения не проходят надёжное распознавание
   и удаление секретов до отправки; аудио отправляется для расшифровки. Не используйте
   реальные чувствительные вложения. Текстовый фильтр также не гарантирует удаление
   всех секретов. store=false у Responses не означает отсутствие всех журналов
   обработки у провайдера. Нужна отдельная проверка политики данных до массового запуска.
8. Для первых тестов указаны gpt-4.1-mini и gpt-4o-transcribe. Это кандидаты,
   не подтверждение доступности в вашем API-проекте. Ошибки доступа/лимитов
   не запускают автоматические повторы и не приводят к отправке клиенту.
9. Применить изменения. Должно прийти «Тестовый помощник запущен. Режим: off».

## Тестовый чат

1. Другой тестовый аккаунт открывает помощника и отправляет /id. Полученный ID
   добавить в SUPPORT_TEST_CHAT_IDS (через запятую, если несколько), перезапустить.
2. В Telegram владельца подключить помощника к аккаунту, разрешив только тестовый
   диалог. Выдать минимальные права ответов; не выдавать права карт/подарков/профиля.
3. В личном чате с помощником отправить /draft. Глобально включатся черновики.
4. Тестовый клиент пишет владельцу. Владелец получает черновик у помощника.
5. Проверить текст; при необходимости ответить самому в исходной личке.
   Для отправки одобренного черновика нажать кнопку. Сам помощник ничего не шлёт.
6. Проверить /stop, ручной перехват, /chats → «Возобновить помощника», повторный клик,
   новое сообщение до одобрения, фото, голосовое и рестарт. Выполнить SAFETY_CHECKS.md.
7. /pending возвращает ожидающие и uncertain-карточки. При uncertain сначала
   проверить исходную личку; сервис не предлагает повторную отправку.
8. /retry НОМЕР_ЧАТА повторяет подготовку последнего вопроса в режиме DRAFT,
   расходуя запросы. Не возобновляет отправку старого ответа.

## Доступ к магазину (отдельный этап подключения)

Без SHOP_READONLY_DATABASE_URL сервис честно сообщает модели, что цены/заказы
неизвестны. Не копировать туда рабочий DATABASE_URL магазина.
Нужна отдельная роль PostgreSQL с CONNECT/USAGE и SELECT только необходимых
столбцов fk_orders и bot_shop_items. Сервис использует явный список столбцов,
WHERE user_id=$1 и read-only транзакции; роль с правами INSERT/UPDATE/DELETE
на таблицы public отклоняется при старте. Создание роли выполняется отдельно
после подготовки и проверки прав, без изменения заказов.

Читаются последние пять заказов (номер, номер FK, статус оплаты, сумма, монетки,
даты), активные тарифы и цены из bot_shop_items. Это не весь каталог (например,
динамические товары требуют отдельного адаптера). Состояние подписки у поставщика
НЕ проверяется и всегда обозначается not_checked. Секреты и коды не читаются.

## Ограничения и следующие обязательные работы

### Обновление 25.10.2026: публичные сведения из интернета

Добавлен research.py. Загрузить его вместе с изменёнными service.py, storage.py,
clients.py, privacy.py, STYLE.md и SERVICE_RULES.md; новые переменные не нужны.
Текущая модель SUPPORT_MODEL используется также для Responses web_search.
Схема проверена по официальной документации, но доступ к web_search на аккаунте
владельца и реальные расходы ещё не проверены. Это следующий живой тест.

Первый запрос формирует черновик либо выбирает фиксированную тему исследования.
При вопросе о публичных моделях/функциях/официальных тарифах выполняется отдельный
поиск, затем второй черновик по найденным источникам. Обычно это 3 запроса модели
вместо 1, плюс платные web_search вызовы (не более 2 на исследование); голосовое
добавляет расшифровку. Счётчик SUPPORT_DAILY_CALL_LIMIT ограничивает запросы API,
но не доллары и не отдельные внутренние поиски. Не повышать лимит до оценки расхода.

Поддерживаются ChatGPT, Claude, Perplexity, Gemini. Поиск ограничен официальными
доменами из research.py. Другие сервисы требуют ручной проверки. Модель не получает
историю, клиентские URL, заказы и вложения В ПОИСКОВОМ запросе: только фиксированные
названия продуктов, темы и текущую дату. Основная модель ответа по-прежнему получает
разрешённую историю и изображения, аудио — модель расшифровки.

Результат поиска принимается только при завершённом web_search_call и наличии
официальных URL в аннотациях цитирования. Если поиск/проверка источников/финальный
ответ не удались, первичный неподтверждённый ответ не показывается: создаётся
черновик с ручной передачей. В карточке — время проверки UTC+5 и ссылки. После
одобрения клиент получает ответ с маркерами [ID] и кликабельными URL источников.
Цены магазина и статусы заказов интернет не заменяет.

Важно: решение о необходимости поиска и интерпретация источников выполняются
моделью. Тесты протокола не гарантируют отсутствие выдуманных фактов или пропуска
поиска. Даже официальный сайт может содержать старую страницу. AUTO не включён,
нужно проверить живые ответы, соответствие ссылок фактам, даты и разные формулировки.

Живые тесты после деплоя:
1. «Нужна нейросеть для документов» → короткое уточнение без жалоб на каталог.
2. «Какие модели сейчас доступны в ChatGPT?» → источники и время проверки либо
   честная ручная передача. При ошибке поиск не считать подключённым успешно.
3. «Сколько у вас стоит Claude?» → без данных магазина не выдавать официальный
   долларовый тариф за цену нашего магазина.
4. /chats → пауза → возобновление; старая кнопка возобновления не отменяет черновик.
5. /stop во время исследования; устаревший результат не предлагается к отправке.

Источник реализации: https://developers.openai.com/api/docs/guides/tools-web-search

### Остальные ограничения

Нет AUTO, автоматического решения возвратов, долговременного профиля предпочтений,
ежедневной сводки и полной проверки активаций. Карточки черновиков отдельные;
единая обновляемая карточка обращения ещё не реализована. Альбомы с несколькими
картинками не собираются: используется вложение последнего актуального сообщения.
Тексты сообщений и черновиков хранятся 7 суток в тестовом сервисе, удаляются
ежечасной очисткой; резервные копии Volume и сообщения Telegram живут отдельно.
Перед настоящими клиентами утвердить сроки хранения, оповещение о помощнике,
оценить качество и расходы, дополнить адаптеры и реализовать проверенный AUTO.

Локальная проверка: python -B -m unittest discover -s tests -p 'test_support*.py'.
Не запускать сервис с реальными ключами вместо тестов.
