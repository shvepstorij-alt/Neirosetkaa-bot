# Часть 40 — aichongz.top (9527 Agent API) · 14.10.2026

## Главное правило (Александр 14.10.2026)
Через aichongz автоматически активируются **только ChatGPT Plus и Claude Pro**.
Все Max (и ChatGPT Go / Pro) aichongz не берёт — они идут через другие сайты или вручную, как раньше.
- Залить в пул aichongz коды другого тарифа нельзя: панель, `/add_gpt_codes` и меню бота отвечают «Коды НЕ добавлены».
- Проверка товара при загрузке (по названию с сайта):
  - код **другого сервиса** (Claude в пуле ChatGPT и наоборот) или товар с **Max** → помечается, в выдачу не идёт, на сайт не отправляется;
  - «похоже на другой тариф» (например «ChatGPT Pro» в пуле Plus) → только **предупреждение «Проверь тариф»**: слово «Pro» в китайском названии Plus-товара может значить другое, рабочий код не выбрасывается. Если тариф правда не тот — удали коды из пула.
- Тариф Claude по названию: «Max 5x» (латинская x) и любое название с «Max» теперь — Max (раньше незнакомое название считалось Pro, и заказ Max мог получить код Pro на любом сайте).
- При оплате Max/Go код aichongz не выдаётся; если активный сайт — aichongz, такой тариф берёт следующий сайт даже при выключенном фолбэке.
- В панели у сайта подпись «только Plus» / «только Pro», а без ключа — «⚠️ нет ключа API»; сделать его активным без ключа нельзя.

## Что сделано
Новый сайт авто-активации **aichongz.top** подключён для ChatGPT и Claude через официальный API продавца
(«9527 Agent API v1», контракт 2026-10-14-r14). Клиент API — новый файл `agent9527.py`.

### Как бот работает с сайтом
- Каждый запрос подписан (HMAC-SHA256, nonce, время). Ключ и секрет — только из переменных Railway.
- **Перед отправкой** бот спрашивает сам код (`/cards/query`):
  - код не нашего агента / отозван / код Claude в пуле ChatGPT (и наоборот) → код помечается, берётся следующий, на сайт ничего не уходит;
  - по коду уже есть **чужой** заказ → новый код НЕ берётся (риск двух подписок), ручной режим и сообщение Александру с подробностями.
- Отправка (`/redemptions`) с ключом идемпотентности, который сохраняется в базе (`settings: a9527:<КОД>`) **до** запроса.
  Обрыв / 5xx / тайм-аут → сначала проверка кода, потом повтор тем же ключом и теми же байтами. Второй заказ не создаётся.
- Ответ 201 — это «заказ создан», а не успех. Успех — только `status=success` **нашего** заказа.
- `manual_review` — НЕ отказ и НЕ возврат: код за клиентом, Александру — «напиши продавцу», бот следит дальше.
- `failed` с активным автоповтором сайта — ещё идёт, ждём.
- `failed` и сайт освободил код → клиенту «попробуй ещё раз» (один раз). Вторая неудача, или клиент не повторил за 6 часов, или сайт код не освободил → ручной режим, новых заказов бот не создаёт.
- Неясный исход → «обрабатывается», фоновое слежение раз в 3 минуты (`a9527_watch_loop`) доводит заказ: успех записывает и пишет клиенту, провал / проверку / 6+ часов без итога — Александру.

### ChatGPT
- Отдельная задача `_run_a9527_gpt_job` — никакой логики bypriceactivate (маршруты iOS/Филиппины, `/query`, слежение за claimed) коды aichongz не касаются.
- Клиент вставляет тот же Session JSON со страницы chatgpt.com/api/auth/session — сайт получает его строкой.
- Аккаунт **уже с подпиской** (по `session.account.planType`): код aichongz не отправляется (как сайт ведёт себя поверх подписки — документация не говорит); заказ передаётся bypriceactivate по его правилам, при отсутствии его кодов — ручной режим. Переключатель: `AICHONGZ_GPT_ON_PAID=1`.
- Фолбэк bypriceactivate → другой сайт aichongz **не** берёт (иначе код ушёл бы в чужую браузерную активацию). aichongz работает как основной сайт или как запасной при **пустом** пуле bypriceactivate (выбор кода при оплате).
- Вторая активация по заказу, если по другому коду на aichongz уже идёт заказ, блокируется.

### Claude
- aichongz — ещё один сайт цепочки (по Organization ID). Без Session Key сайт по умолчанию принимает только **Pro**; Max-коды отклонятся до списания.
- Свой заказ на сайте бот узнаёт по `clientOrderNo = cl-<номер заказа>-…`; старый чужой успех по тому же коду не принимается.
- Кнопки «код цел / код потрачен → другой сайт» для aichongz сначала спрашивают сайт: при живом заказе / manual_review перенос запрещён.

### Пул кодов
- Загрузка в панели и `/add_gpt_codes`: коды aichongz проверяются пакетно, видно **товар** по данным сайта; чужие коды помечаются.
  Коды bypriceactivate больше не проверяются на bpa, если их грузят в другой сайт (раньше Claude-коды любого сайта метились «потраченными»).
- Явный выбор выключенного сайта (нет ключей) — отказ «коды НЕ добавлены», а не тихая заливка в пул bypriceactivate.
- Возврат в пул кодов aichongz — только по ответу сайта «свободен»: чистка ChatGPT и Claude, кнопка «В пул» в панели (иначе — «принудительно»), массовый возврат, кнопки возврата в меню бота, кнопка клиента «Активировали вручную», перевыбор при паузе, смена на bpa. Код с отправкой на сайт не возвращается вовсе — его ведёт слежение.
- Код, уже уходивший на сайт для другого заказа, новому клиенту не активируется (ручной режим).
- Отказы в панели (длинные причины) показываются окном, а не исчезающей подсказкой.
- Исправлено попутно: миграция в `db.py` при **каждом** запуске снимала пометки `invalid/error` (в т.ч. «пришёл уже потраченным»). Теперь — один раз.

### Админ-панель и кнопки бота (проверено в браузере)
- Сайт aichongz в списке «Провайдер активации» (ChatGPT и Claude), подпись «только Plus / только Pro», без ключа — «⚠️ нет ключа API» и запрет делать его активным (панель и кнопки в чате бота).
- «➕ Коды»: Plus/Pro добавляются с проверкой на сайте (целы / товар / «Проверь тариф»); Go, Max и любые коды без ключа — окно «Коды НЕ добавлены».
- «Ждущие коды»: у кодов aichongz своё состояние («бот следит сам», «ручная проверка у продавца», «реши»), без кнопки записи через bypriceactivate.
- «В пул» (панель, массовый возврат, кнопки в чате бота, «Активировали вручную» у клиента) — для aichongz только если сайт подтвердил «свободен»; иначе код помечается, Александру — причина.

## Чек-лист после деплоя
1. Спросить продавца: есть ли **белый список IP** у ключа. У Railway исходящий IP не постоянный — либо снять ограничение, либо дать продавцу IP/домен.
2. Права ключа: `cards:read`, `redeem:create` (и `orders:retry` по желанию).
3. Залить 1–2 кода aichongz через панель → выбрать сайт **aichongz.top** → посмотреть «Товар по данным aichongz» и что коды «целы».
4. `/gpt_why <код>` — разбор кода aichongz прямо с сайта.
5. Тестовая активация на своём **free**-аккаунте ChatGPT; для Claude — Pro-код и свой Organization ID.
6. Порядок сайтов: ChatGPT — активный сайт и фолбэк в панели; Claude — цепочка сама ставит вперёд сайт, где больше свободных кодов.

## Что НЕ проверено вживую
Сайт недоступен из среды разработки (сеть блокирует домен), поэтому всё проверено на макете сервера,
построенном строго по документации (подпись, nonce, идемпотентность, все состояния): 100 + 11 проверок, плюс весь прежний набор тестов.
Реальные названия товаров, тексты отказов и значения `autoRetryState` у продавца могут отличаться — неизвестное трактуется
в безопасную сторону (ждём / ручной режим), а не «провал → второй код».
